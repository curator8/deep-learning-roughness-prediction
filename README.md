# Deep Learning Roughness Prediction

CNN-based pipeline for predicting PBR roughness maps from albedo textures, with ablation studies, quantitative metrics, and a Three.js comparison viewer.

This project treats material-map generation as an image-to-image regression task:

- input: `albedo.png`
- target: `roughness.png`
- models: U-Net with skip connections and a no-skip autoencoder baseline
- training: `data/train`
- held-out evaluation: `data/test`
- outputs: saved train/test metrics, model checkpoints, exported texture maps, and an interactive browser viewer

The repository contains two main parts:

- Python code for dataset loading, training, ablations, metric reporting, and texture export
- A FastAPI backend for serving the trained PyTorch model online
- A Three.js app for comparing the original and predicted roughness maps on a mesh

## Example Results

The pipeline exports:

- `outputs/ablation_results.json` with final metrics
- `outputs/prediction_preview.png` with side-by-side albedo, target roughness, and predicted roughness
- `simple-textured-mesh/static/predictions/` assets for browser-based comparison

The default exported sample is `dirt_01`.

## Ablation Summary

Current ablation metrics are selected by held-out test MAE:

| Model | MAE | RMSE | Cosine Similarity |
|---|---:|---:|---:|
| U-Net with skip connections | 0.0891 | 0.1130 | 0.9978 |
| Autoencoder without skips | 0.1431 | 0.1630 | 0.9982 |

Interpretation:

- The U-Net achieves lower `MAE` and `RMSE`, so it fits the roughness targets more accurately.
- The autoencoder baseline performs worse on direct reconstruction error.
- This ablation supports the claim that skip connections help preserve useful spatial detail for this image-to-image regression task.

## Python Files

- `texture-model-pipeline/texture_dataset.py`
  Loads paired `albedo.png` and `roughness.png` files and applies paired training augmentation.
- `texture-model-pipeline/texture_model.py`
  Defines the U-Net, the no-skip autoencoder baseline, train/test evaluation helpers, and metrics.
- `texture-model-pipeline/run_texture_model.py`
  Clean executable entry point for training, ablations, held-out test metrics, and exporting textures.
- `texture-model-pipeline/requirements.txt`
  Python libraries needed to run the training and export pipeline.
- `texture-model-pipeline/theory-notes.md`
  Cleaned theory notes explaining the PBR maps, models, metrics, and Three.js pipeline.
- `experimentation-file.ipynb`
  Original exploratory notebook kept for reference.

## Three.js Viewer

The viewer lives in `simple-textured-mesh/`.

It loads local comparison files from:

- `simple-textured-mesh/static/predictions/albedo_input.png`
- `simple-textured-mesh/static/predictions/roughness_original.png`

Those files are generated by `run_texture_model.py`.

The Predict button sends an albedo image to the FastAPI backend at `/predict`.
The backend loads `outputs/unet_skip_connections.pth` by default, runs PyTorch inference, and returns a PNG roughness map for the Three.js material.

## Run Locally

### 1. Train and export textures

From the `portfolio/texture-model-pipeline/` folder:

```bash
pip install -r requirements.txt
python run_texture_model.py
```

This will:

- train both model variants using `data/train`
- evaluate each epoch on `data/test`
- use paired augmentation on the training samples
- save best held-out test metrics in `outputs/ablation_results.json`
- save a checkpoint for the best model
- export the albedo, original roughness, and predicted roughness maps into `simple-textured-mesh/static/predictions/`

### 2. Start the Three.js viewer

From the `simple-textured-mesh/` folder:

```bash
npm install
npm run dev
```

Then open the local Vite URL in the browser.

### 3. Run the FastAPI backend locally

From the repository root:

```bash
pip install -r backend/requirements.txt
pip install torch --index-url https://download.pytorch.org/whl/cpu
uvicorn backend.main:app --reload --host 0.0.0.0 --port 8000
```

The API exposes:

- `GET /health`
- `POST /predict` with multipart field `file`

If your frontend runs somewhere other than `http://localhost:5173`, set:

```bash
ALLOWED_ORIGINS=http://localhost:5173,http://your-frontend-origin
```

### 4. Test locally with Docker

From the repository root:

```bash
docker compose up --build
```

Then open:

- Frontend: `http://localhost:5173`
- Backend health check: `http://localhost:8000/health`

## Notes

- The default hyperparameters are tuned for a small dataset: 80 epochs, batch size 4, AdamW, weight decay, Smooth L1 loss, gradient clipping, and ReduceLROnPlateau.
- Training augmentation uses random crops, flips, 90-degree rotations, and light albedo color jitter while keeping roughness aligned.
- By default, the exported sample comes from `data/test`.
- You can change the exported sample with:

```bash
python run_texture_model.py --sample-name rocky_trail_01
```

- You can disable augmentation for comparison with:

```bash
python run_texture_model.py --no-augment
```
